Okay, based on the provided 3GPP NAS specification section (5.5.1.2.8) and its context, here's a breakdown of the key procedural steps the AMF takes in response to abnormal events during the *initial* registration procedure:

**A. Lower Layer Failure:**

*   If a lower layer failure occurs *before* REGISTRATION COMPLETE and while timer T3550 is running:
    *   AMF aborts the initial registration procedure locally.
    *   AMF enters `5GMM-REGISTERED` state.
    *   AMF does *not* resend REGISTRATION ACCEPT.
    *   If a new 5G-GUTI was assigned: AMF considers *both* old and new 5G-GUTIs valid for a period. (Exception: If old 5G-GUTI was from another AMF, current AMF doesn't need to retain it.)
    *   If the UE subsequently uses the old 5G-GUTI, the AMF may initiate Identification procedure followed by a Generic UE Configuration Update procedure.

**B. Protocol Error in REGISTRATION REQUEST:**

*   AMF sends a REGISTRATION REJECT with one of the following 5GMM cause values:
    *   `#96` Invalid mandatory information
    *   `#99` Information element non-existent or not implemented
    *   `#100` Conditional IE error
    *   `#111` Protocol error, unspecified

**C. T3550 Timeout:**

*   On the *first* expiry:
    *   AMF retransmits REGISTRATION ACCEPT.
    *   AMF resets and restarts T3550.
*   Repeats retransmission *four* times.
*   On the *fifth* expiry:
    *   AMF aborts the initial registration procedure.
    *   AMF enters `5GMM-REGISTERED` state.
    *   If a new 5G-GUTI was allocated, the AMF shall consider both the old and the new 5G-GUTIs as valid until the old 5G-GUTI can be considered as invalid by the AMF or the 5GMM context which has been marked as de-registered in the AMF is released. If the old 5G-GUTI was allocated by an AMF other than the current AMF, the current AMF does not need to retain the old 5G-GUTI. During this period, if the old 5G-GUTI is used by the UE in a subsequent message, the AMF acts as specified for case a).

**D. Redundant REGISTRATION REQUEST (Initial Registration) *before* REGISTRATION COMPLETE:**

*   **Case 1: Information elements *differ*:**
    *   AMF aborts the previously initiated registration procedure.
    *   AMF progresses the new initial registration procedure.
*   **Case 2: Information elements do *not* differ:**
    *   AMF resends REGISTRATION ACCEPT.
    *   AMF restarts T3550 (retransmission counter *not* incremented).

**E. Multiple REGISTRATION REQUEST messages with 5GS registration type IE set to "initial registration" received and no REGISTRATION ACCEPT message or REGISTRATION REJECT message has been sent.**

*   **Case 1: Information elements *differ*:**
    *   AMF aborts the previously initiated registration procedure.
    *   AMF progresses the new initial registration procedure.
*   **Case 2: Information elements do *not* differ:**
    *   The network shall continue with the previous the registration procedure for initial registration and shall ignore the second REGISTRATION REQUEST message.

**F. REGISTRATION REQUEST (Initial Registration) received in `5GMM-REGISTERED` state:**

*   Network may initiate 5GMM common procedures (Authentication).
*   If UE is determined to be genuine and is already registered:
    *   Any existing 5GMM context is deleted.
    *   The new REGISTRATION REQUEST is progressed.
*   Otherwise (network considers the UE not genuine based on the authentication procedure):
    *   The network shall maintain the 5GMM-context, if any, unchanged.

**G. REGISTRATION REQUEST (Mobility or Periodic Registration Update) received *before* REGISTRATION COMPLETE (Initial Registration):**

*   AMF stops T3550.
*   AMF considers the allocated 5G-GUTI from the initial registration as valid.
*   AMF progresses the mobility/periodic registration update procedure (as per 5.5.1.3).

**H. DEREGISTRATION REQUEST received *before* REGISTRATION COMPLETE (Initial Registration):**

*   AMF aborts the initial registration procedure.
*   AMF progresses the de-registration procedure (as per 5.5.2.2).

**I. Invalid or Unacceptable UE Security Capabilities:**

*   AMF sends a REGISTRATION REJECT.
*   The specific 5GMM cause value is up to network implementation.

**J. Initial registration request from a UE not supporting CAG is rejected due to CAG restrictions**

*   AMF sends a REGISTRATION REJECT with a 5GMM cause value other than the 5GMM cause #76 (Not authorized for this CAG or authorized for CAG cells only).
