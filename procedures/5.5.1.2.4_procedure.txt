```text
- **Procedure Name:** Initial registration accepted by the network
- **Triggering Conditions:**
    - Initial registration request is accepted by the network

- **Steps:**
    1. The AMF sends a REGISTRATION ACCEPT message to the UE.
    2. The AMF assigns and includes a TAI list in the REGISTRATION ACCEPT message.  If the REGISTRATION REQUEST was received over non-3GPP access, the TAI list contains a single TAI.
    3. The AMF may include service area restrictions in the Service area list IE in the REGISTRATION ACCEPT message.
    4. The AMF may include a list of equivalent PLMNs in the REGISTRATION ACCEPT message.
    5. If the ESI bit of the 5GMM capability IE of the REGISTRATION REQUEST message is set to "equivalent SNPNs supported", the AMF of a SNPN may include a list of equivalent SNPNs in the REGISTRATION ACCEPT message.
    6. If the AMF supports and accepts the use of WUS assistance information for the UE, then the AMF shall determine the negotiated UE paging probability information for the UE and include it in the Negotiated WUS assistance information IE in the REGISTRATION ACCEPT message (if the UE is not performing the initial registration for emergency services).
    7. If the UE sets the NR-PSSI bit to "NR paging subgrouping supported" in the 5GMM capability IE in the REGISTRATION REQUEST message and the AMF supports and accepts the use of PEIPS assistance information for the UE, then the AMF shall determine the Paging subgroup ID for the UE, and shall include it in the Negotiated PEIPS assistance information IE in the REGISTRATION ACCEPT message or in the Updated PEIPS assistance information IE in the CONFIGURATION UPDATE COMMAND message as part of the registration procedure.
    8. If the UE set the UN-PER bit to "unavailability period supported" in the 5GMM capability IE in the REGISTRATION REQUEST message and the AMF supports and accepts the use of unavailability period for the UE, then the AMF shall set the UN-PER bit to "unavailability period supported" in the 5GS network feature support IE in the REGISTRATION ACCEPT message. Furthermore, if the AMF is able to determine an unavailability period duration for the UE based on satellite coverage availability information and the UE is registered over a satellite NG-RAN access, the AMF shall store the determined unavailability period duration and provide the determined unavailability period duration to the UE by including the unavailability period duration in the Unavailability configuration IE in the REGISTRATION ACCEPT message. If the AMF is able to determine the start of unavailability period based on satellite coverage availability information, the AMF shall store the determined start of unavailability period and provide the determined start of unavailability period to the UE by including the start of unavailability period in the Unavailability configuration IE in the REGISTRATION ACCEPT message.
    9. The AMF shall include the LADN information which consists of the determined LADN DNNs for the UE and LADN service area(s) available in the current registration area in the LADN information IE of the REGISTRATION ACCEPT message.
    10. If the UE has set the LADN-DS bit to "LADN per DNN and S-NSSAI supported" in the 5GMM capability IE of the REGISTRATION REQUEST message and the extended LADN information is available for the UE, the AMF shall include the extended LADN information which consists of the determined LADN DNNs for the UE, the S-NSSAIs associated with the determined LADN DNNs for the UE and in the allowed NSSAI or partially allowed NSSAI, and LADN service area(s) available in the current registration area in the Extended LADN information IE in the Registration accept type 6 IE container IE of the REGISTRATION ACCEPT message.
    11. During the initial registration procedure, if the AMF has not allocated a new 5G-GUTI by the generic UE configuration update procedure, the AMF shall include in the REGISTRATION ACCEPT message the new assigned 5G-GUTI together with the assigned TAI list.
    12. If the UE has set the CAG bit to "CAG supported" in the 5GMM capability IE of the REGISTRATION REQUEST message and the AMF needs to update the "CAG information list" stored in the UE, the AMF shall include the CAG information list IE or the Extended CAG information list IE in the REGISTRATION ACCEPT message.
    13. If a 5G-GUTI or the SOR transparent container IE is included in the REGISTRATION ACCEPT message, the AMF shall start timer T3550 and enter state 5GMM-COMMON-PROCEDURE-INITIATED.
    14. If the Operator-defined access category definitions IE, the Extended emergency number list IE, the CAG information list IE or the Extended CAG information list IE are included in the REGISTRATION ACCEPT message, the AMF shall start timer T3550 and enter state 5GMM-COMMON-PROCEDURE-INITIATED.
    15. If the UE has set the RCMAP bit to "Sending of REGISTRATION COMPLETE message for negotiated PEIPS assistance information supported" in the 5GMM capability IE of the REGISTRATION REQUEST message and if the Negotiated PEIPS assistance information IE is included in the REGISTRATION ACCEPT message, the AMF shall start timer T3550 and enter state 5GMM-COMMON-PROCEDURE-INITIATED.
    16. If the UE is not in NB-N1 mode and the UE has set the RACS bit to "RACS supported" in the 5GMM Capability IE of the REGISTRATION REQUEST message, the AMF may include either a UE radio capability ID IE or a UE radio capability ID deletion indication IE in the REGISTRATION ACCEPT message. If the UE radio capability ID IE or the UE radio capability ID deletion indication IE is included in the REGISTRATION ACCEPT message, the AMF shall start timer T3550 and enter state 5GMM-COMMON-PROCEDURE-INITIATED.
    17. The AMF shall include the MICO indication IE in the REGISTRATION ACCEPT message only if the MICO indication IE was included in the REGISTRATION REQUEST message, the AMF supports and accepts the use of MICO mode.
    18. The AMF shall include an active time value in the T3324 IE in the REGISTRATION ACCEPT message if the UE requested an active time value in the REGISTRATION REQUEST message and the AMF accepts the use of MICO mode and the use of active time.
    19. The AMF shall include the T3512 value IE in the REGISTRATION ACCEPT message only if the REGISTRATION REQUEST message was sent over the 3GPP access.
    20. The AMF shall include the non-3GPP de-registration timer value IE in the REGISTRATION ACCEPT message only if the REGISTRATION REQUEST message was sent over the non-3GPP access.
    21. If the UE requests "control plane CIoT 5GS optimization" in the 5GS update type IE, indicates support of control plane CIoT 5GS optimization in the 5GMM capability IE and the AMF decides to accept the requested CIoT 5GS optimization and the registration request, the AMF shall indicate "control plane CIoT 5GS optimization supported" in the 5GS network feature support IE of the REGISTRATION ACCEPT message.
    22. The AMF may include the T3447 value IE set to the service gap time value in the REGISTRATION ACCEPT message if the UE has indicated support for service gap control in the REGISTRATION REQUEST message and a service gap time value is available in the 5GMM context.
    23. If the UE has indicated support for the control plane CIoT 5GS optimizations, and the AMF decides to activate the congestion control for transport of user data via the control plane, then the AMF shall include the T3448 value IE in the REGISTRATION ACCEPT message.
    24. If the UE in NB-N1 mode is using control plane CIoT 5GS optimization and the network is configured to provide the truncated 5G-S-TMSI configuration for control plane CIoT 5GS optimizations, the AMF shall include the Truncated 5G-S-TMSI configuration IE in the REGISTRATION ACCEPT message and set the "Truncated AMF Set ID value" and the "Truncated AMF Pointer value" in the Truncated 5G-S-TMSI configuration IE based on network policies. The AMF shall start timer T3550 and enter state 5GMM-COMMON-PROCEDURE-INITIATED.
    25. If the UE has included the service-level device ID set to the CAA-level UAV ID in the Service-level-AA container IE of the REGISTRATION REQUEST message, and the specified conditions are met, the AMF shall initiate the UUAA-MM procedure with the UAS-NF and shall include a service-level-AA pending indication in the Service-level-AA container IE of the REGISTRATION ACCEPT message. The AMF shall store in the UE 5GMM context that a UUAA procedure is pending. The AMF shall start timer T3550 and enter state 5GMM-COMMON-PROCEDURE-INITIATED. If the REGISTRATION REQUEST message was received over non-3GPP access, the AMF shall not initiate UUAA-MM procedure.
    26. If the UE has included the service-level device ID set to the CAA-level UAV ID in the Service-level-AA container IE of the REGISTRATION REQUEST message, and if the UE has a valid aerial UE subscription information, the UUAA procedure is to be performed during the registration procedure according to operator policy, and there is a valid successful UUAA result for the UE in the UE 5GMM context, then the AMF shall include a service-level-AA response in the Service-level-AA container IE of the REGISTRATION ACCEPT message and set the SLAR field in the service-level-AA response to "Service level authentication and authorization was successful".
    27. If the AMF determines that the UUAA-MM procedure needs to be performed for a UE, the AMF has not received the service-level device ID set to the CAA-level UAV ID in the Service-level-AA container IE of the REGISTRATION REQUEST message from the UE and the AMF decides to accept the UE to be registered for other services than UAS services based on the user's subscription data and the operator policy, the AMF shall accept the initial registration request and shall mark in the UE's 5GMM context that the UE is not allowed to request UAS services.
    28. If the UE supports MINT, the AMF may include the List of PLMNs to be used in disaster condition IE in the REGISTRATION ACCEPT message.
    29. If the UE supports MINT, the AMF may include the Disaster roaming wait range IE in the REGISTRATION ACCEPT message.
    30. If the UE supports MINT, the AMF may include the Disaster return wait range IE in the REGISTRATION ACCEPT message.
    31. If the AMF received the list of TAIs from the satellite NG-RAN, and determines that, by UE subscription and operator's preferences, any but not all TAIs in the received list of TAIs is forbidden for roaming or for regional provision of service, the AMF shall include the TAI(s) in the corresponding forbidden TAI IE in the REGISTRATION ACCEPT message.
    32. If the UE has set the Reconnection to the network due to RAN timing synchronization status change (RANtiming) bit to "Reconnection to the network due to RAN timing synchronization status change supported" in the 5GMM capability IE of the REGISTRATION REQUEST message, the AMF may include the RAN timing synchronization IE with the RecReq bit set to "Reconnection requested" in the REGISTRATION ACCEPT message.
    33. If the AMF receives the initial registration request along with the mobile IAB-indication over N2 reference point from UE and the UE is authorized to operate as an MBSR based on the subscription information and local policy, the AMF shall include the Feature authorization indication IE in the REGISTRATION ACCEPT message and shall set the MBSRAI field to "authorized to operate as MBSR". If the AMF receives the initial registration request along with the mobile IAB-indication over N2 reference point from UE and the UE is not authorized to operate as an MBSR based on the subscription information and local policy but can operate as a UE, the AMF shall include the Feature authorization indication IE in the REGISTRATION ACCEPT message and shall set the MBSRAI field to "not authorized to operate as MBSR but allowed to operate as a UE".
    34. If the UE supports user plane positioning using LCS-UPP, SUPL, or both, the AMF shall set the LCS-UPP bit, the SUPL bit, or both in the 5GS network feature support IE of the REGISTRATION ACCEPT message as specified in 3GPP TS 24.572.
    35. Upon receipt of the REGISTRATION ACCEPT message, the UE shall reset the registration attempt counter, enter state 5GMM-REGISTERED and set the 5GS update status to 5U1 UPDATED.
    36. If the REGISTRATION ACCEPT message included a T3512 value IE, the UE shall use the value in the T3512 value IE as periodic registration update timer (T3512).
    37. If the REGISTRATION ACCEPT message include a T3324 value IE, the UE shall use the value in the T3324 value IE as active timer (T3324).
    38. If the REGISTRATION ACCEPT message included a non-3GPP de-registration timer value IE, the UE shall use the value in non-3GPP de-registration timer value IE as non-3GPP de-registration timer.
    39. If the REGISTRATION ACCEPT message contains a configured NSSAI IE with a new configured NSSAI for the current PLMN or SNPN and optionally the mapped S-NSSAI(s) for the configured NSSAI for the current PLMN or SNPN, an NSSRG information IE with a new NSSRG information, an Alternative NSSAI IE with a new alternative NSSAI, an S-NSSAI location validity information in the Registration accept type 6 IE container IE with a new S-NSSAI location validity information, or an On-demand NSSAI IE with a new on-demand NSSAI or an updated slice deregistration inactivity timer value, the UE shall return a REGISTRATION COMPLETE message to the AMF to acknowledge the successful update of the network slicing information.
    40. If the UE has set the RCMAN bit to "Sending of REGISTRATION COMPLETE message for NSAG information supported" in the 5GMM capability IE of the REGISTRATION REQUEST message and if REGISTRATION ACCEPT message contains the NSAG information IE, the UE shall return REGISTRATION COMPLETE message to the AMF to acknowledge the reception of the NSAG information IE.
    41. If the REGISTRATION ACCEPT message contains the CAG information list IE or the Extended CAG information list IE and the UE had set the CAG bit to "CAG supported" in the 5GMM capability IE of the REGISTRATION REQUEST message, the UE shall replace the "CAG information list" stored in the UE under the specified conditions.
    42. If the REGISTRATION ACCEPT message contains the Operator-defined access category definitions IE, the Extended emergency number list IE ,the CAG information list IE or the Extended CAG information list IE, the UE shall return a REGISTRATION COMPLETE message to the AMF to acknowledge reception of the operator-defined access category definitions, the extended local emergency numbers list or the "CAG information list".
    43. If the UE has set the RCMAP bit to "Sending of REGISTRATION COMPLETE message for negotiated PEIPS parameters supported" in the 5GMM capability IE of the REGISTRATION REQUEST message and if REGISTRATION ACCEPT message contains the Negotiated PEIPS assistance information IE, the UE shall return REGISTRATION COMPLETE message to the AMF to acknowledge the reception of the Negotiated PEIPS assistance information IE.
    44. If the REGISTRATION ACCEPT message contains the UE radio capability ID IE or the UE radio capability ID deletion indication IE, the UE shall return a REGISTRATION COMPLETE message to the AMF to acknowledge reception of the UE radio capability ID IE or the UE radio capability ID deletion indication IE.
    45. Upon receiving a REGISTRATION COMPLETE message, the AMF shall stop timer T3550 and change to state 5GMM-REGISTERED. The 5G-GUTI, if sent in the REGISTRATION ACCEPT message, shall be considered as valid, the PEIPS assistance information, if sent in the REGISTRATION ACCEPT message, shall be considered as valid, and the UE radio capability ID, if sent in the REGISTRATION ACCEPT, shall be considered as valid.

- **Decision Points:**
    - REGISTRATION REQUEST message received over non-3GPP access? → Yes: Include single TAI in the TAI list / No: Include multiple TAIs in the TAI list.
    - Initial registration procedure is for emergency services? → Yes: AMF shall not include a list of equivalent SNPNs in the REGISTRATION ACCEPT message / No: AMF may include a list of equivalent SNPNs in the REGISTRATION ACCEPT message
    - UE requested active time and AMF accepts MICO and use of active time? → Yes: include active time value in T3324 IE / No: do not include active time value in T3324 IE
    - UE supports control plane CIoT 5GS optimization and AMF decides to accept? → Yes: Indicate support in 5GS network feature support IE / No: Do not indicate support.
    - AMF determines UUAA-MM procedure needs to be performed for a UE but has not received the service-level device ID set to the CAA-level UAV ID in the Service-level-AA container IE of the REGISTRATION REQUEST message and the AMF decides to accept the UE to be registered for other services than UAS services based on the user's subscription data and the operator policy → Accept initial registration request and mark in the UE's 5GMM context that the UE is not allowed to request UAS services
    - 5GS update type IE was included in the REGISTRATION REQUEST message with the SMS requested bit set to "SMS over NAS supported", and SMSF selection is successful → AMF shall set the SMS allowed bit of the 5GS registration result IE to "SMS over NAS allowed" in the REGISTRATION ACCEPT message / If SMSF selection is not successful, SMS activation via the SMSF is not successful, the AMF does not allow the use of SMS over NAS, the SMS requested bit of the 5GS update type IE was set to "SMS over NAS not supported" in the REGISTRATION REQUEST message; or the 5GS update type IE was not included in the REGISTRATION REQUEST message, then the AMF shall set the SMS allowed bit of the 5GS registration result IE to "SMS over NAS not allowed" in the REGISTRATION ACCEPT message.
    - The UE sets the NSSAA bit in the 5GMM capability IE to "Network slice-specific authentication and authorization not supported"?
    - AMF determines a disaster condition applies to the PLMN with disaster condition, and the UE is allowed to be registered for disaster roaming services → AMF shall set the Disaster roaming registration result value bit in the 5GS registration result IE to "no additional information" in the REGISTRATION ACCEPT message. If the AMF determines that the UE can be registered to the PLMN for normal service, the AMF shall set the Disaster roaming registration result value bit in the 5GS registration result IE to "request for registration for disaster roaming services accepted as registration not for disaster roaming services" in the REGISTRATION ACCEPT message

- **State Transitions:**
    - After sending REGISTRATION ACCEPT, the AMF starts T3550 (if 5G-GUTI or SOR transparent container IE included) and enters 5GMM-COMMON-PROCEDURE-INITIATED
    - After sending REGISTRATION ACCEPT, the AMF starts T3550 (if Operator-defined access category definitions IE, the Extended emergency number list IE, the CAG information list IE or the Extended CAG information list IE are included) and enters 5GMM-COMMON-PROCEDURE-INITIATED
    - After sending REGISTRATION ACCEPT, the AMF starts T3550 (if the UE has set the RCMAP bit to "Sending of REGISTRATION COMPLETE message for negotiated PEIPS assistance information supported" in the 5GMM capability IE of the REGISTRATION REQUEST message and if the Negotiated PEIPS assistance information IE is included) and enters 5GMM-COMMON-PROCEDURE-INITIATED
    - After sending REGISTRATION ACCEPT, the AMF starts T3550 (if the UE is not in NB-N1 mode and the UE has set the RACS bit to "RACS supported" in the 5GMM Capability IE of the REGISTRATION REQUEST message and either a UE radio capability ID IE or a UE radio capability ID deletion indication IE is included) and enters 5GMM-COMMON-PROCEDURE-INITIATED
    - After receiving a REGISTRATION COMPLETE message, the AMF stops timer T3550 and change to state 5GMM-REGISTERED.
    - Upon receipt of the REGISTRATION ACCEPT message, the UE enters state 5GMM-REGISTERED and set the 5GS update status to 5U1 UPDATED.

- **Important Information Elements:**
    - 5GS registration type IE: Indicates the type of registration requested by the UE (e.g., initial registration, emergency registration)
    - TAI list: List of Tracking Area Identities assigned to the UE.
    - Service area list IE: List of service area restrictions.
    - Equivalent PLMNs: List of PLMNs considered equivalent to the registered PLMN.
    - 5GMM capability IE: Contains UE capabilities related to 5GMM procedures.
    - Requested NSSAI: Network Slice Selection Assistance Information requested by the UE.
    - Allowed NSSAI: Network Slice Selection Assistance Information allowed by the network.
    - Extended rejected NSSAI IE: Indicates which S-NSSAI(s) have been rejected by the network, along with a cause.
    - Negotiated WUS assistance information IE: The negotiated UE paging probability information for the UE.
    - Negotiated PEIPS assistance information IE: The Paging subgroup ID for the UE.
    - UE radio capability ID IE:  A network assigned UE radio capability ID
    - UE radio capability ID deletion indication IE: An indication the network-assigned UE radio capability IDs associated with the RPLMN or RSNPN
    - MICO indication IE: Contains parameters related to MICO mode.
    - 5GS network feature support IE: Indicates the features supported by the network.
    - Registration accept type 6 IE container IE: A container for type 6 IEs.
    - Truncated 5G-S-TMSI configuration IE: Contains Truncated 5G-S-TMSI configuration parameters.
    - Service-level-AA container IE: Contains parameters related to service-level authentication and authorization for UAVs
    - Network slicing indication IE: Indicates whether the subscription data for network slicing has changed.
    - CAG information list IE: Contains information about Closed Access Groups (CAGs).
    - SOR transparent container IE: Contains the steering of roaming information.
    - NSSAI inclusion mode IE: Indicates the NSSAI inclusion mode.
    - RAT utilization control IE: Indicates the RAT restriction.
    - RAN timing synchronization IE: RAN timing synchronization status.
    - Unavailability configuration IE: Contains configuration for UE unavailability.
    - Feature authorization indication IE: Authorisation to operate as MBSR or not
    - Discontinuous coverage maximum time offset IE: Max timer value for discontinuous coverage
```
