The provided text describes the actions taken by the AMF (Access and Mobility Management Function) and UE (User Equipment) during the "Initial Registration Accepted by the Network" phase of the 5G registration procedure. Key procedural steps for both AMF and UE are:

**AMF (Network) Actions:**

1.  **Processing Registration Request:**
    *   During emergency registration, the AMF skips mobility, access, regional, subscription, and CAG restrictions.

2.  **Sending Registration Accept:** The AMF sends a REGISTRATION ACCEPT message to the UE if the initial registration request is accepted.

3.  **Handling UE Capabilities:** Stores the received 5GMM capability, S1 UE network capability, and UE security capability from the UE.

4.  **TAI List Assignment:**
    *   Assigns and includes a TAI (Tracking Area Identity) list to the UE, excluding mixed NB-N1 and non-NB-N1 TAIs.
    *   Includes a single TAI if the request was over non-3GPP access.

5.  **Service Area Restrictions:** May include service area restrictions.

6.  **Equivalent PLMN/SNPN Lists:**
    *   May include a list of equivalent PLMNs or SNPNs in the REGISTRATION ACCEPT message.
    *   For SNPNs, this is conditional on the ESI bit in the UE's 5GMM capability.
    *   The AMF of a PLMN shall not include a list of equivalent SNPNs.
    *   The AMF of an SNPN shall not include a list of equivalent PLMNs.

7.  **LADN Handling:** Determines and includes LADN (Local Area Data Network) information based on the LADN indication IE in the REGISTRATION REQUEST message, UE subscription, location and local configuration. If the UE supports LADN per DNN and S-NSSAI and the extended LADN information is available for the UE, the AMF shall include the extended LADN information which consists of the determined LADN DNNs for the UE, the S-NSSAIs associated with the determined LADN DNNs for the UE and in the allowed NSSAI or partially allowed NSSAI, and LADN service area(s) available in the current registration area in the Extended LADN information IE in the Registration accept type 6 IE container IE of the REGISTRATION ACCEPT message.

8.  **WUS Assistance Information:** Negotiates, stores, and may include Negotiated WUS assistance information (Wake-Up Signal) if supported.

9.  **PEIPS Assistance Information:** Determines, stores, and includes Negotiated PEIPS assistance information (Paging Early Indication to reduce power consumption) if supported.

10. **Unavailability Period:** If the UE set the UN-PER bit to "unavailability period supported" in the 5GMM capability IE in the REGISTRATION REQUEST message and the AMF supports and accepts the use of unavailability period for the UE, then the AMF shall set the UN-PER bit to "unavailability period supported" in the 5GS network feature support IE in the REGISTRATION ACCEPT message. The AMF may determine and provide the unavailability period duration/start to the UE in the Unavailability configuration IE in the REGISTRATION ACCEPT message.

11. **5G-GUTI Reallocation:** Includes the new assigned 5G-GUTI together with the assigned TAI list.

12. **CAG Information:**  If the UE has set the CAG bit to "CAG supported" in the 5GMM capability IE of the REGISTRATION REQUEST message and the AMF needs to update the "CAG information list" stored in the UE, the AMF shall include the CAG information list IE or the Extended CAG information list IE in the REGISTRATION ACCEPT message.

13. **Timer Initiation (T3550):** Starts timer T3550 and enters `5GMM-COMMON-PROCEDURE-INITIATED` state under certain conditions, like sending a new 5G-GUTI or SOR transparent container, Operator-defined access category definitions IE, the Extended emergency number list IE, the CAG information list IE or the Extended CAG information list IE,  or if certain capabilities related to PEIPS or RACS are negotiated.

14. **MICO Mode:** Handles MICO (Mobile Initiated Connection Only) mode indication and active time values.

15. **Timer Values:** Includes T3512 (periodic registration timer), non-3GPP de-registration timer values if applicable.

16. **CIoT 5GS Optimization:** Indicates support for control plane CIoT 5GS optimization if accepted. May include T3448 value IE if decides to activate the congestion control for transport of user data via the control plane.

17. **Truncated 5G-S-TMSI Configuration:** If the UE in NB-N1 mode is using control plane CIoT 5GS optimization; and the network is configured to provide the truncated 5G-S-TMSI configuration for control plane CIoT 5GS optimizations, the AMF shall include the Truncated 5G-S-TMSI configuration IE in the REGISTRATION ACCEPT message and set the "Truncated AMF Set ID value" and the "Truncated AMF Pointer value" in the Truncated 5G-S-TMSI configuration IE based on network policies.

18. **UUAA Procedure:** If the UE has included the service-level device ID set to the CAA-level UAV ID in the Service-level-AA container IE of the REGISTRATION REQUEST message, and if the UUAA procedure is to be performed during the registration procedure according to operator policy, the AMF shall initiate the UUAA-MM procedure with the UAS-NF as specified in 3GPP TS 23.256 [6AB] and shall include a service-level-AA pending indication in the Service-level-AA container IE of the REGISTRATION ACCEPT message.

19. **MINT:** May include the List of PLMNs to be used in disaster condition IE, the Disaster roaming wait range IE and the Disaster return wait range IE if the UE supports MINT.

20. **Forbidden TAIs:** May include forbidden TAIs for roaming or regional provision of service.

21. **RAN Timing Synchronization:** May include RAN timing synchronization IE to request UE reconnection.

22. **MBSR Authorization:** May include the Feature authorization indication IE and set the MBSRAI field if the UE is authorized to operate as an MBSR.

23. **Network Feature Support:** Sets bits in the 5GS network feature support IE to indicate support for features like LCS-UPP, SUPL, IMS voice, emergency services, ATSSS, NAPS, paging indication for voice services, reject paging request, paging restriction and ranging and sidelink positioning.

24. **SMS over NAS:** Sets the SMS allowed bit of the 5GS registration result IE based on successful SMSF selection and activation.

25. **NSSAI Handling:** Includes the allowed NSSAI and may include rejected NSSAI, partially rejected NSSAI and pending NSSAI in the REGISTRATION ACCEPT message.  Handles network slice-specific authentication and authorization (NSSAA) indicators and pending NSSAI. May include the On-demand NSSAI IE in the REGISTRATION ACCEPT message. Includes the configured NSSAI for the current PLMN or SNPN. Includes the NSSRG information in the REGISTRATION ACCEPT message. If the UE supports S-NSSAI time validity information and the AMF needs to update the S-NSSAI time validity information, then the AMF shall include the S-NSSAI time validity information IE in the REGISTRATION ACCEPT message. If the UE supports S-NSSAI location validity information and the AMF needs to update the S-NSSAI location validity information, then the AMF shall include the new S-NSSAI location validity information in the Registration accept type 6 IE container IE of the REGISTRATION ACCEPT message. If the UE has set the NSAG bit to "NSAG supported" in the 5GMM capability IE of the REGISTRATION REQUEST message over 3GPP access, the AMF may include the NSAG information IE in the REGISTRATION ACCEPT message. If the UE supports network slice replacement and the AMF determines to provide the mapping information between the S-NSSAI to be replaced and the alternative S-NSSAI to the UE, then the AMF shall include the Alternative NSSAI IE, the Allowed NSSAI IE including the alternative S-NSSAI, if not included in the current allowed NSSAI, and the Configured NSSAI IE including the alternative S-NSSAI, if not included in the current configured NSSAI, in the REGISTRATION ACCEPT message.

26. **Interworking with EPS:** Sets the IWK N26 bit in the 5GS network feature support IE to indicate support for interworking with EPS.

27. **DRX Parameters:** Includes Negotiated DRX parameters, Negotiated NB-N1 mode DRX parameters and Negotiated extended DRX parameters if requested and supported.

28. **SOR Handling:** Includes SOR transparent container IE, if required.

29. **NSSAI Inclusion Mode:** May include the NSSAI inclusion mode IE.

30. **Operator-defined access category definitions:** May include operator-defined access category definitions.

31. **Service Gap Control:** May include the T3447 value IE to indicate the service gap time value.

32. **RAT utilization control:** If the UE indicates support of the RAT utilization control in the REGISTRATION REQUEST message over 3GPP access and the network decides to apply the RAT utilization control, the AMF shall include the RAT utilization control IE in the REGISTRATION ACCEPT message.

33. **Disaster Roaming Services:** If the 5GS registration type IE in the REGISTRATION REQUEST message is set to "disaster roaming initial registration", the AMF shall determine the PLMN with disaster condition and shall set the Disaster roaming registration result value bit in the 5GS registration result IE to "no additional information" or "request for registration for disaster roaming services accepted as registration not for disaster roaming services" in the REGISTRATION ACCEPT message.

34. **Truncated 5G-S-TMSI Configuration:** If the UE in NB-N1 mode is using control plane CIoT 5GS optimization; and the network is configured to provide the truncated 5G-S-TMSI configuration for control plane CIoT 5GS optimizations, the AMF shall include the Truncated 5G-S-TMSI configuration IE in the REGISTRATION ACCEPT message and set the "Truncated AMF Set ID value" and the "Truncated AMF Pointer value" in the Truncated 5G-S-TMSI configuration IE based on network policies.

35. **UE radio capability ID:** If the UE is not in NB-N1 mode, the UE has set the RACS bit to "RACS supported" in the 5GMM Capability IE of the REGISTRATION REQUEST message and the REGISTRATION ACCEPT message includes a UE radio capability ID IE, the AMF shall include the UE radio capability ID IE in the REGISTRATION ACCEPT message.

36. **N1 NAS signalling connection release bit:** If the UE indicates support of the N1 NAS signalling connection release in the REGISTRATION REQUEST message and the network decides to accept the N1 NAS signalling connection release, then the AMF shall set the N1 NAS signalling connection release bit to "N1 NAS signalling connection release supported" in the 5GS network feature support IE of the REGISTRATION ACCEPT message.

37. **Paging Indication for Voice Services Bit:** If the UE indicates support of the paging indication for voice services in the REGISTRATION REQUEST message and the network decides to accept the paging indication for voice services, then the AMF shall set the paging indication for voice services bit to "paging indication for voice services supported" in the 5GS network feature support IE of the REGISTRATION ACCEPT message.

38. **Reject Paging Request Bit:** If the UE indicates support of the reject paging request in the REGISTRATION REQUEST message and the network decides to accept the reject paging request, then the AMF shall set the reject paging request bit to "reject paging request supported" in the 5GS network feature support IE of the REGISTRATION ACCEPT message.

39. **Paging Restriction Bit:** If the UE indicates support of the paging restriction in the REGISTRATION REQUEST message, and the AMF sets the reject paging request bit or the N1 NAS signalling connection release bit or both of them in the 5GS network feature support IE of the REGISTRATION ACCEPT message, and the network decides to accept the paging restriction, then the AMF shall set the paging restriction bit to "paging restriction supported" in the 5GS network feature support IE of the REGISTRATION ACCEPT message.

40. **Ranging and Sidelink Positioning Bit:** If the UE indicates support of ranging and sidelink positioning in the REGISTRATION REQUEST message and the network supports and accepts the use of ranging and sidelink positioning, the AMF shall set the ranging and sidelink positioning support bit to "Ranging and sidelink positioning supported" in the 5GS network feature support IE of the REGISTRATION ACCEPT message.

41. **Discontinuous Coverage:** If the UE supports discontinuous coverage and is registered over a satellite NG-RAN access, the AMF may for discontinuous coverage include the Discontinuous coverage maximum time offset IE in the REGISTRATION ACCEPT message.

42. **Unavailability configuration:** If the UE supports discontinuous coverage and is registered over a satellite NG-RAN access, the AMF may for discontinuous coverage include the Unavailability configuration IE in the REGISTRATION ACCEPT message.

**UE (Device) Actions:**

1.  **TAI List Handling:** Deletes the old TAI list and stores the received TAI list.

2.  **Service Area Restriction Handling:** Acts according to subclause 5.3.5 if service area restrictions are received.

3.  **Equivalent PLMN/SNPN List Handling:**
    *   Stores the list of equivalent PLMNs/SNPNs.
    *   Removes PLMNs in forbidden list (if not for emergency services).
    *   Adds the registered PLMN/SNPN to the list.
    *   Replaces the stored list on each receipt. Deletes if no list is received.

4.  **LADN Handling:** Stores received LADN information. If there exists one or more LADN DNNs which are included in the LADN indication IE of the REGISTRATION REQUEST message and are not included in the LADN information IE and Extended LADN information IE in the Registration accept type 6 IE container IE of the REGISTRATION ACCEPT message, the UE considers such LADN DNNs as not available in the current registration area.

5.  **Registration Attempt Counter:** Resets the registration attempt counter.

6.  **State Transition:** Enters `5GMM-REGISTERED` state and sets the 5GS update status to `5U1 UPDATED`.

7.  **Timer Handling:**
    *   Uses the received T3512 value as the periodic registration update timer.
    *   Uses the received T3324 value as the active timer.
    *   Uses the value in non-3GPP de-registration timer value IE as non-3GPP de-registration timer.

8.  **Registration Complete Message:**
    *   Sends a REGISTRATION COMPLETE message to the AMF in specific cases, such as when network slicing information, CAG information, Operator-defined access category definitions, Extended emergency number list, Negotiated PEIPS assistance information IE, UE radio capability ID IE or UE radio capability ID deletion indication IE, Truncated 5G-S-TMSI configuration IE or service-level-AA pending indication in the Service-level-AA container IE are received.

9.  **SMS Allowed:** Considers the SMS allowed bit of the 5GS registration result IE as applicable for both accesses (if registered over both 3GPP and non-3GPP).

10. **5GS Registration Result:** Handles the 5GS registration result IE to determine registration access (3GPP, non-3GPP, or both) and initiate de-registration procedures on the other access if necessary.

11. **NSSAI Handling:** Stores allowed NSSAI, handles the partially rejected NSSAI, extended rejected NSSAI, network slice-specific authentication and authorization (NSSAA) indicators, pending NSSAI, configured NSSAI and NSAG information. Delete the network slicing information and the NSSAI inclusion mode for each and every PLMN or SNPN except for the current PLMN or SNPN as specified in subclause 4.6.2.2 and remove all tracking areas from the list of "5GS forbidden tracking areas for roaming" which were added due to rejection of S-NSSAI due to "S-NSSAI not available in the current registration area".

12. **Interworking with EPS:** Stores the received interworking without N26 interface indicator.

13. **Network Feature Support:** Provides the IMS voice over PS session indicator, the Emergency services support indicator, and the Emergency services fallback indicator, location services indicator (5G-LCS), the network support for ATSSS and the network support for non-3GPP access path switching to upper layers.

14. **Access Identity:** Acts as a UE with access identity 1 or access identity 2 configured for MPS or MCS.

15. **DRX Parameters:** Stores and uses the received Negotiated DRX parameters, Negotiated NB-N1 mode DRX parameters and Negotiated extended DRX parameters.

16. **SOR Handling:** Stores the received SOR counter and proceeds as specified in 3GPP TS 23.122 [5] annex C, if the SOR transparent container IE included in the REGISTRATION ACCEPT message successfully passes the integrity check.

17. **NSSAI Inclusion Mode:** Operates in the NSSAI inclusion mode indicated in the NSSAI inclusion mode IE over the current access within the current PLMN and its equivalent PLMN(s), if any, or the current SNPN ,in the current registration area.

18. **Operator-defined access category definitions:** Stores the received operator-defined access category definitions for the RPLMN.

19. **Service Gap Control:** Stores the new T3447 value, erase any previous stored T3447 value if exists and use the new T3447 value with the timer T3447 next time it is started, if the REGISTRATION ACCEPT message contains the T3447 value IE.

20. **T3448 value:** If the T3448 value IE is present in the received REGISTRATION ACCEPT message and the value indicates that this timer is neither zero nor deactivated, the UE shall stop timer T3448 if it is running and start timer T3448 with the value provided in the T3448 value IE.

21. **Truncated 5G-S-TMSI Configuration:** If the REGISTRATION ACCEPT message contains the Truncated 5G-S-TMSI configuration IE, then the UE shall store the included truncated 5G-S-TMSI configuration and return a REGISTRATION COMPLETE message to the AMF to acknowledge reception of the truncated 5G-S-TMSI configuration.

22. **UE radio capability ID:** If the UE is not in NB-N1 mode, the UE has set the RACS bit to "RACS supported" in the 5GMM Capability IE of the REGISTRATION REQUEST message and the REGISTRATION ACCEPT message includes a UE radio capability ID IE, the UE shall store the UE radio capability ID.

23. **Service-level-AA:** If the UE has included the service-level device ID set to the CAA-level UAV ID in the Service-level-AA container IE of the REGISTRATION REQUEST message and the REGISTRATION ACCEPT message contains the service-level-AA pending indication in the Service-level-AA container IE, the UE shall return a REGISTRATION COMPLETE message to the AMF to acknowledge reception of the service-level-AA pending indication.

24. **MINT:** If the UE receives the List of PLMNs to be used in disaster condition IE, the Disaster roaming wait range IE and the Disaster return wait range IE in the REGISTRATION ACCEPT message and the UE supports MINT, the UE shall delete the stored parameters and store the new parameters received in the message.

25. **Disaster Roaming Services:** If the UE indicates "disaster roaming initial registration" in the 5GS registration type IE in the REGISTRATION REQUEST message and the 5GS registration result IE value in the REGISTRATION ACCEPT message is set to "request for registration for disaster roaming service accepted as registration not for disaster roaming service", the UE shall consider itself registered for normal service. If the UE receives the forbidden TAI(s) for the list of "5GS forbidden tracking areas for roaming" IE or the forbidden TAI(s) for the list of "5GS forbidden tracking areas for regional provision of service" IE in the REGISTRATION ACCEPT message, the UE shall store the TAI(s) belonging to the serving PLMN or equivalent PLMN(s) included in the IE, if not already stored, into the corresponding list.

26. **RAN timing synchronization:** If the UE supporting the reconnection to the network due to RAN timing synchronization status change receives the RAN timing synchronization IE with the RecReq bit set to "Reconnection requested" in the REGISTRATION ACCEPT message, the UE shall operate as specified in subclauses 5.3.1.4, 5.5.1.3.2 and 5.6.1.1.

27. **Discontinuous Coverage:** If the UE receives, the Discontinuous coverage maximum time offset IE in the REGISTRATION ACCEPT message, the UE shall replace any previously received discontinuous coverage maximum time offset value.

28. **RAT utilization control:** If the REGISTRATION ACCEPT message received over 3GPP access contains the RAT utilization control IE, the UE shall store the received RAT utilization control information together with the PLMN identity of the current PLMN in the list of "PLMNs with associated RAT restrictions" and replace the previously stored one associated with the current PLMN, if any, with the newly received RAT utilization control information.

This summarizes the core exchange and processing steps performed by the AMF and UE when the network accepts the UE's initial registration request.
