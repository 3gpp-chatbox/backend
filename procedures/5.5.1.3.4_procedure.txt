Based on the provided text, here's a breakdown of the key procedural steps from the AMF and UE perspective during a successful mobility and periodic registration update, focusing on actions and conditions:

**AMF (Network) Actions:**

*   **Receives REGISTRATION REQUEST:** The AMF receives a REGISTRATION REQUEST message from the UE.
*   **Handles NSSAI Compatibility (Non-3GPP Access):** If the request is over non-3GPP access and the N3IWF or TNGF only supports a subset of the allowed NSSAI, and the UE doesn't support slice-based selection, the AMF accepts the request.
*   **Stops Timers:** Stops timers T3513 (if paging with non-3GPP access was involved and Allowed PDU session status IE is present) and T3565.
*   **Stores UE Capabilities:** Stores the 5GMM, S1 UE network, and UE security capabilities received from the UE.
*   **5G-GUTI Handling:** Reallocates a 5G-GUTI if not already done via generic UE configuration update and includes it in the REGISTRATION ACCEPT message.
*   **CAG Information List Handling:** Includes the CAG information list or Extended CAG information list IE in the REGISTRATION ACCEPT message if the UE supports CAG and the AMF needs to update the CAG information.
*   **Starts Timer T3550:** Starts timer T3550 and enters state 5GMM-COMMON-PROCEDURE-INITIATED under certain conditions when specific IEs are included in the REGISTRATION ACCEPT message: 5G-GUTI, SOR transparent container IE, Operator-defined access category definitions IE, the Extended emergency number list IE ,the CAG information list IE, the Extended CAG information list IE, PEIPS assistance information IE, UE radio capability ID IE, Truncated 5G-S-TMSI configuration IE, On-demand NSSAI IE, Service-level-AA container IE and UE supports MINT.
*   **TAI List Handling:** May include a new TAI list in the REGISTRATION ACCEPT message, ensuring it's consistent (either all NB-N1 mode TAIs or all non-NB-N1 mode TAIs).
*   **Equivalent PLMN List:** May include a list of equivalent PLMNs.  The AMF of a PLMN shall not include a list of equivalent SNPNs.
*    **Equivalent SNPN List:** If the ESI bit of the 5GMM capability IE of the REGISTRATION REQUEST message is set to "equivalent SNPNs supported", the AMF of a SNPN may include a list of equivalent SNPNs in the REGISTRATION ACCEPT message. The AMF of an SNPN shall not include a list of equivalent PLMNs.
*   **Service Area Restrictions:**  May include new service area restrictions.
*   **MICO Mode Handling:** Includes the MICO indication IE in the REGISTRATION ACCEPT message only if the MICO indication IE was included in the REGISTRATION REQUEST message and MICO mode is supported and accepted by the AMF.
*   **Active Time Handling:** Includes an active time value in the T3324 IE in the REGISTRATION ACCEPT message if the UE requested an active time value in the REGISTRATION REQUEST message, and the AMF accepts the use of MICO mode and the use of active time.
*   **Timer Values:** May include T3512 value IE (if over 3GPP access) and non-3GPP de-registration timer value IE (if over non-3GPP access).
*   **5GS Network Feature Support IE:** Sets bits in the 5GS network feature support IE to indicate support for N1 NAS signalling connection release, paging indication for voice services, reject paging request, paging restriction, control plane CIoT 5GS optimization, emergency services fallback, and ranging and sidelink positioning based on UE capabilities and network decisions.
*   **Congestion Control Activation:** Includes the T3448 value IE in the REGISTRATION ACCEPT message if the AMF decides to activate the congestion control for transport of user data via the control plane.
*   **Inter-System Change Handling (S1 to N1):** Performs integrity checks and security context handling for inter-system changes from S1 to N1 mode, including security mode control procedures if necessary.
*   **UUAA Handling:** Initiates the UUAA-MM procedure with the UAS-NF if the UE included the service-level device ID set to the CAA-level UAV ID in the Service-level-AA container IE of the REGISTRATION REQUEST message, the UE has a valid aerial UE subscription information, the UUAA procedure is to be performed during the registration procedure according to operator policy, and there is no valid successful UUAA result for the UE in the UE 5GMM context.
*   **MINT support:** If the UE supports MINT, the AMF may include the List of PLMNs to be used in disaster condition IE, the Disaster roaming wait range IE and the Disaster return wait range IE in the REGISTRATION ACCEPT message.
*   **Forbidden TAI(s):** If the AMF received the list of TAIs from the satellite NG-RAN as described in 3GPP TS 23.501 [8], and determines that, by UE subscription and operator's preferences, any but not all TAIs in the received list of TAIs is forbidden for roaming or for regional provision of service, the AMF shall include the TAI(s) in the Forbidden TAI(s) for the list of "5GS forbidden tracking areas for roaming" IE, the Forbidden TAI(s) for the list of "5GS forbidden tracking areas for regional provision of service" IE or both in the REGISTRATION ACCEPT message.
*   **Feature Authorization Indication IE:** If the AMF receives the mobility and periodic registration request along with along with the mobile IAB-indication over N2 reference point (see TS 38.413 [31]) from an UE, the AMF shall include the Feature authorization indication IE in the REGISTRATION ACCEPT message.
*   **5GS Registration Result IE:** Includes the 5GS registration result IE in the REGISTRATION ACCEPT message to indicate if the UE is registered for 3GPP access, non-3GPP access, or both. If the UE is not currently registered for emergency services and the emergency registered bit of the 5GS registration result IE in the REGISTRATION ACCEPT message is set to "Registered for emergency services", the AMF shall indicate to the SMF to perform a local release of all non-emergency PDU sessions (associated with 3GPP access if it is due to CAG restrictions).
*   **NSSAI Handling:** Includes Allowed NSSAI, Rejected NSSAI (or Extended rejected NSSAI), Partially rejected NSSAI, Pending NSSAI as needed.
*   **Network slicing:** Includes the Network slicing indication IE with the Network slicing subscription change indication set to "Network slicing subscription changed" in the REGISTRATION ACCEPT message if the UDM has indicated that the subscription data for network slicing has changed.
*    **On-demand NSSAI:** If the UE indicates support for network slice usage control and the AMF determines to provide the on-demand NSSAI, the AMF shall include the On-demand NSSAI IE in the REGISTRATION ACCEPT message.
*   **Configured NSSAI:** May include a new configured NSSAI for the current PLMN or SNPN based on various conditions (e.g., no requested NSSAI, invalid S-NSSAI in request, etc.).
*   **NSSRG information:** If a new configured NSSAI for the current PLMN or SNPN is included, the subscription information includes the NSSRG information, and the NSSRG bit in the 5GMM capability IE of the REGISTRATION REQUEST message is set to: "NSSRG supported", then the AMF shall include the NSSRG information in the REGISTRATION ACCEPT message.
*   **PDU Session Handling:** If the S-NSSAI(s) associated with the existing PDU session(s) of the UE is not included in the requested NSSAI (i.e. Requested NSSAI IE or Requested mapped NSSAI IE) of the REGISTRATION REQUEST message, the AMF shall perform a local release of the PDU session(s) associated with the S-NSSAI(s) except for a PDU session associated with DNN and S-NSSAI in the AMF onboarding configuration data and shall request the SMF to perform a local release of those PDU session(s).
*   **5GS Registration Result IE for NSSAA:** The REGISTRATION ACCEPT message includes the 5GS registration result IE with the "NSSAA to be performed" indicator set to indicate that the network slice-specific authentication and authorization procedure will be performed by the network, if the allowed NSSAI is not included in the REGISTRATION ACCEPT message.
*   **NSAG information:** If the UE has set the NSAG bit to "NSAG supported" in the 5GMM capability IE of the REGISTRATION REQUEST message over 3GPP access, the AMF may include the NSAG information IE in the REGISTRATION ACCEPT message.
*   **Alternative NSSAI:** If the UE supports network slice replacement and the AMF determines to provide the mapping information between the S-NSSAI to be replaced and the alternative S-NSSAI to the UE, then the AMF shall include the Alternative NSSAI IE and the Allowed NSSAI IE including the alternative S-NSSAI, if not included in the current allowed NSSAI, in the REGISTRATION ACCEPT message.
*   **Partially allowed NSSAI:** If the UE has indicated the support for partial network slice and the AMF determines one or more S-NSSAI(s) in the requested NSSAI are to be included in the partially allowed NSSAI as specified in subclause 4.6.2.11, the AMF shall include the Partially allowed NSSAI IE in the Registration accept type 6 IE container IE of the REGISTRATION ACCEPT message.
*   **Uplink Data Status Handling:** Handles the Uplink data status IE if included in the REGISTRATION REQUEST message, indicating the SMF to re-establish the user-plane resources for the corresponding PDU session, if any, or notifying the SMF that reactivation of the user-plane resources for the corresponding PDU session(s) associated with non-3GPP access cannot be performed, including the PDU session reactivation result IE in the REGISTRATION ACCEPT message to indicate the successfully re-established user-plane resources for the corresponding PDU sessions, if any.
*   **Single access PDU sessions and MA PDU sessions handling:** The AMF shall perform a local release of all those PDU sessions which are not in 5GSM state PDU SESSION INACTIVE on the AMF side associated with the access type the REGISTRATION REQUEST message is sent over, but are indicated by the UE as being in 5GSM state PDU SESSION INACTIVE. and shall include a PDU session status IE in the REGISTRATION ACCEPT message to indicate which PDU sessions associated with the access type the REGISTRATION ACCEPT message is sent over are not in 5GSM state PDU SESSION INACTIVE in the AMF;
*   **EPS Bearer Context Status IE:** Includes an EPS bearer context status IE if interworking with EPS is supported and EPS bearer contexts exist.
*   **5GS Network Feature Support IE for interworking with EPS:** If the UE included S1 mode supported indication in the REGISTRATION REQUEST message, the AMF supporting interworking with EPS shall set the IWK N26 bit to either: "interworking without N26 interface not supported" if the AMF supports N26 interface or "interworking without N26 interface supported" if the AMF does not support N26 interface in the 5GS network feature support IE in the REGISTRATION ACCEPT message.
*   **MPS/MCS Indicator:** Sets the MPS/MCS indicator bits in the 5GS network feature support IE based on subscription information.
*   **NAS Signalling Connection Release:** May delay releasing the NAS signalling connection based on the "Follow-on request pending" indicator, V2X/A2X authorization, and 5G ProSe authorization.
*   **Requested DRX parameters IE:** If the Requested DRX parameters IE was included in the REGISTRATION REQUEST message, the AMF shall include the Negotiated DRX parameters IE in the REGISTRATION ACCEPT message and replace any stored Negotiated DRX parameter and use it for the downlink transfer of signalling and user data.
*   **Service gap control IE:** If the UE has indicated support for service gap control in the REGISTRATION REQUEST message, a service gap time value is available in the 5GMM context, the AMF may include the T3447 value IE set to the service gap time value in the REGISTRATION ACCEPT message.
*   **Ciphering keys IE:** If the UE requests ciphering keys for ciphered broadcast assistance data in the REGISTRATION REQUEST message and the AMF has valid ciphering key data applicable to the UE's subscription and current tracking area, then the AMF shall include the ciphering key data in the Ciphering key data IE of the REGISTRATION ACCEPT message.
*   **WUS assistance information IE:** If the UE supports WUS assistance information and the AMF supports and accepts the use of WUS assistance information for the UE, then the AMF shall determine the negotiated UE paging probability information for the UE, store it in the 5GMM context of the UE, and if the UE does not have an active emergency PDU session, the AMF shall include it in the Negotiated WUS assistance information IE in the REGISTRATION ACCEPT message.
*   **UN-PER IE:** If the UE sets the Unavailability type to "unavailability due to UE reasons" in the Unavailability information IE in the REGISTRATION REQUEST message, then the AMF shall: set the Unavailability period duration and the Start of the unavailability period to the value provided by the UE and the AMF shall store the Start of unavailability period value and the Unavailability period duration.
*   **Disaster roaming:** If the 5GS registration type IE is set to "disaster roaming mobility registration updating", the AMF shall determine the PLMN with disaster condition.
*   **RAN timing synchronization IE:** If the UE supporting the reconnection to the network due to RAN timing synchronization status change receives the RAN timing synchronization IE with the RecReq bit set to "Reconnection requested" in the REGISTRATION ACCEPT message.
*   **RAT utilization control IE:** If the UE indicates support of the RAT utilization control in the REGISTRATION REQUEST message over 3GPP access and the network decides to apply the RAT utilization control, the AMF shall include the RAT utilization control IE in the REGISTRATION ACCEPT message.
*   **MBSR authorization:** If the UE operating as MBSR receives the MBSRAI field of the Feature authorization indication IE in the REGISTRATION ACCEPT message.
*   **Sends REGISTRATION ACCEPT:** Finally, the AMF sends the REGISTRATION ACCEPT message to the UE.
*   **Stops Timer T3550 and changes to state 5GMM-REGISTERED:** Upon receiving a REGISTRATION COMPLETE message.

**UE (Mobile) Actions:**

*   **Sends REGISTRATION REQUEST:** The UE sends a REGISTRATION REQUEST message.
*   **TAI List Handling:** Deletes the old TAI list and stores the received TAI list. If there is no TAI list received, the UE shall consider the old TAI list as valid.
*   **Equivalent PLMN List:** Stores the list of equivalent PLMNs.
*   **Equivalent SNPN List:** Stores the list of equivalent SNPNs.
*   **Service Area Restrictions:** Acts on new service area restrictions as specified in subclause 5.3.5.
*   **MICO Handling:** Treats all TAIs in the current PLMN as a registration area and deletes its old TAI list if the REGISTRATION ACCEPT message includes an MICO indication IE indicating "all PLMN registration area allocated".
*   **T3512 Value Handling:** Restarts T3512 with the new value received in the T3512 value IE.
*   **Receives REGISTRATION ACCEPT:** The UE receives a REGISTRATION ACCEPT message.
*   **Resets Counters and Enters State:** Resets the registration attempt counter and service request attempt counter, enters state 5GMM-REGISTERED and sets the 5GS update status to 5U1 UPDATED.
*   **Timer Handling:** If the REGISTRATION ACCEPT message included a T3512 value IE, the UE shall use the value in T3512 value IE as periodic registration update timer (T3512). If the T3512 value IE is not included, the UE shall use the value currently stored, e.g. from a prior REGISTRATION ACCEPT message.
*   **Timer Handling:** If the REGISTRATION ACCEPT message included a non-3GPP de-registration timer value IE, the UE shall use the value in non-3GPP de-registration timer value IE as non-3GPP de-registration timer. If non-3GPP de-registration timer value IE is not included, the UE shall use the value currently stored, e.g. from a prior REGISTRATION ACCEPT message. If non-3GPP de-registration timer value IE is not included and there is no stored non-3GPP de-registration timer value in the UE, the UE shall use the default value of the non-3GPP de-registration timer.
*   **REGISTRATION COMPLETE:** If the REGISTRATION ACCEPT message contains a 5G-GUTI, the UE shall return a REGISTRATION COMPLETE message to the AMF to acknowledge the received 5G-GUTI, stop timer T3519 if running, and delete any stored SUCI.
*   **Network slicing:** If the REGISTRATION ACCEPT message contains a Network slicing indication IE with the Network slicing subscription change indication set to "Network slicing subscription changed", the UE shall return a REGISTRATION COMPLETE message to the AMF to acknowledge the successful update of the network slicing information.
*   **Operator-defined access category definitions, Extended emergency number list, CAG information list:** If the REGISTRATION ACCEPT message contains the Operator-defined access category definitions IE, the Extended emergency number list IE, the CAG information list IE or the Extended CAG information list IE, the UE shall return a REGISTRATION COMPLETE message to the AMF to acknowledge reception of the operator-defined access category definitions or the extended local emergency numbers list or the CAG information list.
*   **Negotiated PEIPS assistance information IE:** If the REGISTRATION ACCEPT message contains the Negotiated PEIPS assistance information IE, the UE shall return a REGISTRATION COMPLETE message to the AMF to acknowledge reception of the Negotiated PEIPS assistance information IE.
*   **UE radio capability ID IE and UE radio capability ID deletion indication IE:** If the REGISTRATION ACCEPT message contains the UE radio capability ID IE or the UE radio capability ID deletion indication IE, the UE shall return a REGISTRATION COMPLETE message to the AMF to acknowledge reception of the UE radio capability ID IE or the UE radio capability ID deletion indication IE.
*   **CAG Information List Handling:** Updates its stored "CAG information list" based on the received CAG information list IE or the Extended CAG information list IE. May enter `5GMM-REGISTERED.LIMITED-SERVICE` or `5GMM-REGISTERED.PLMN-SEARCH` state and initiate cell selection procedures based on CAG-ID authorization.
*   **T3448 Handling:** Starts timer T3448 with the received value if present and valid.
*   **S1 Mode:** The UE supporting S1 mode shall operate in the mode for inter-system interworking with EPS as follows:
*   **Alternative NSSAI IE:** If the UE receives the Alternative NSSAI IE in the REGISTRATION ACCEPT message, the UE shall store the alternative NSSAI as specified in subclause 4.6.2.2.
*   **Network slicing:** If the REGISTRATION ACCEPT message contains the Network slicing indication IE with the Network slicing subscription change indication set to "Network slicing subscription changed", the UE shall delete the network slicing information and the NSSAI inclusion mode for each and every PLMN or SNPN except for the current PLMN or SNPN as specified in subclause 4.6.2.2 and remove all tracking areas from the list of "5GS forbidden tracking areas for roaming" which were added due to rejection of S-NSSAI due to "S-NSSAI not available in the current registration area".
*   **Rejected NSSAI handling:** The UE receiving the rejected NSSAI in the REGISTRATION ACCEPT message takes the following actions based on the rejection cause in the rejected S-NSSAI(s).
*   **Pending NSSAI:** The UE that has indicated the support for network slice-specific authentication and authorization receiving the pending NSSAI in the REGISTRATION ACCEPT message shall store the S-NSSAI(s) in the pending NSSAI as specified in subclause 4.6.2.2.
*   **LADN information:** The UE, upon receiving the REGISTRATION ACCEPT message with the LADN information IE, shall delete its old LADN information (if any) and store the received new LADN information.
*   **EPS bearer contexts IE:** If the EPS bearer context status IE is included in the REGISTRATION ACCEPT message, the UE shall locally delete all those QoS flow descriptions and all associated QoS rules, if any, which are associated with inactive EPS bearer contexts as indicated by the AMF in the EPS bearer context status IE.
*   **RAT utilization control IE:** If the REGISTRATION ACCEPT message received over 3GPP access contains the RAT utilization control IE, the UE shall store the received RAT utilization control information together with the PLMN identity of the current PLMN in the list of "PLMNs with associated RAT restrictions" and replace the previously stored one associated with the current PLMN, if any, with the newly received RAT utilization control information.
*   **MBSR authorization:** If the UE operating as MBSR receives the MBSRAI field of the Feature authorization indication IE in the REGISTRATION ACCEPT message, the UE NAS layer informs the lower layers of the status of MBSR authorization as specified in subclause 5.35A.4 of 3GPP TS 23.501 [8].
*   **SNPN NID handling:** If the ESI bit of the 5GMM capability IE of the REGISTRATION REQUEST message is set to "equivalent SNPNs supported", and the serving SNPN changes, the UE shall determine the SNPN identity of the RSNPN from the NID received in the REGISTRATION ACCEPT message and the MCC and the MNC of the new 5G-GUTI.
*   **RANTiming synchronization IE:** If the UE supporting the reconnection to the network due to RAN timing synchronization status change receives the RAN timing synchronization IE with the RecReq bit set to "Reconnection requested" in the REGISTRATION ACCEPT message.
*   **Truncated 5G-S-TMSI configuration IE:** If the REGISTRATION ACCEPT message contains the Truncated 5G-S-TMSI configuration IE, then the UE shall store the included truncated 5G-S-TMSI configuration and return a REGISTRATION COMPLETE message to the AMF to acknowledge reception of the truncated 5G-S-TMSI configuration.
*   **Unavailability configuration IE:** If the UE receives the Unavailability configuration IE with a value of the unavailability period duration in the REGISTRATION ACCEPT message, then the UE may either delete a UE determined value and start using the received value, or use a UE determined value.
*   **UE radio capability ID deletion indication IE/UE radio capability ID IE:** If the UE is not in NB-N1 mode, the UE has set the RACS bit to "RACS supported" in the 5GMM Capability IE of the REGISTRATION REQUEST message, and the REGISTRATION ACCEPT message includes a UE radio capability ID deletion indication IE set to "Network-assigned UE radio capability IDs deletion requested" or a UE radio capability ID IE.
*   **DRX Parameters:** Stores new values for Negotiated DRX parameters IE, Negotiated NB-N1 mode DRX parameters IE and Negotiated extended DRX parameters IE.
