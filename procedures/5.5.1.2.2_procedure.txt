- **Procedure Name:** Initial Registration
- **Triggering Conditions:**
    - The UE is in state 5GMM-DEREGISTERED and performs initial registration for 5GS services.
    - The UE is in state 5GMM-DEREGISTERED and performs initial registration for emergency services.
    - The UE is in state 5GMM-DEREGISTERED and performs initial registration for SMS over NAS.
    - The UE is in state 5GMM-DEREGISTERED and moves from GERAN/UTRAN to NG-RAN coverage after a GPRS attach/routing area update or 5G-SRVCC to UTRAN without a subsequent EPS attach/TAU or registration procedure.
    - The UE is in state 5GMM-DEREGISTERED and performs initial registration for onboarding services in SNPN.
    - The UE is in state 5GMM-DEREGISTERED and performs initial registration for disaster roaming services.
    - The UE is in state 5GMM-DEREGISTERED and performs initial registration to come out of unavailability period and resume normal services.
- **Steps:**
    1. The UE sends a REGISTRATION REQUEST message to the AMF.
    2. The UE starts timer T3510.
    3. If timer T3502 is running, the UE stops timer T3502.
    4. If timer T3511 is running, the UE stops timer T3511.
- **Decision Points:**
    - UE was previously registered in S1 mode before entering EMM-DEREGISTERED, received "interworking without N26 interface not supported", and has a valid native 4G-GUTI and EPS security context? → Yes: create a 5G-GUTI mapped from the native 4G-GUTI, include it in the 5GS mobile identity IE, include the UE status IE with the EMM registration status set to "UE is not in EMM-REGISTERED state", and include an ATTACH REQUEST message in the EPS NAS message container IE / No: continue to the next decision point.
    - UE is registering with a PLMN and holds a valid 5G-GUTI that was previously assigned, over 3GPP access or non-3GPP access, by the same PLMN with which the UE is performing the registration? → Yes: indicate the 5G-GUTI in the 5GS mobile identity IE / No: continue to the next decision point.
    - UE is registering with a SNPN, the UE holds a valid 5G-GUTI that was previously assigned, over 3GPP access or non-3GPP access, by the same SNPN with which the UE is performing the registration, and the UE is not initiating the initial registration for onboarding services in SNPN? → Yes: indicate the 5G-GUTI in the 5GS mobile identity IE / No: continue to the next decision point.
    - UE is registering with a PLMN and holds a valid 5G-GUTI that was previously assigned, over 3GPP access or non-3GPP access, by an equivalent PLMN? → Yes: indicate the 5G-GUTI in the 5GS mobile identity IE / No: continue to the next decision point.
    - UE is registering with an SNPN, the UE holds a valid 5G-GUTI that was previously assigned, over 3GPP access or non-3GPP access, by an equivalent SNPN identified by a globally unique SNPN identity, and the UE is not initiating the initial registration for onboarding services in SNPN? → Yes: indicate the 5G-GUTI in the 5GS mobile identity IE and include the NID of the equivalent SNPN in the NID IE / No: continue to the next decision point.
   - UE is registering with a PLMN and holds a valid 5G-GUTI that was previously assigned, over 3GPP access or non-3GPP access, by any other PLMN? → Yes: indicate the 5G-GUTI in the 5GS mobile identity IE / No: continue to the next decision point.
    - UE is registering with an SNPN, the UE holds a valid 5G-GUTI that was previously assigned, over 3GPP access or non-3GPP access, by any other SNPN identified by a globally unique SNPN identity, and the UE is not initiating the initial registration for onboarding services in SNPN? → Yes: indicate the 5G-GUTI in the 5GS mobile identity IE and include the NID of the other SNPN in the NID IE / No: continue to the next decision point.
    - A SUCI other than an onboarding SUCI is available, and the UE is not initiating the initial registration for onboarding services in SNPN? → Yes: include the SUCI other than an onboarding SUCI in the 5GS mobile identity IE / No: continue to the next decision point.
    - The UE does not hold a valid 5G-GUTI or SUCI other than an onboarding SUCI, and is initiating the initial registration for emergency services? → Yes: include the PEI in the 5GS mobile identity IE / No: continue to the next decision point.
    - The UE is initiating the initial registration for onboarding services in SNPN? → Yes: include an onboarding SUCI in the 5GS mobile identity IE. / No: continue.
    - The SUCI is included in the 5GS mobile identity IE and the timer T3519 is not running? → Yes: the UE shall start timer T3519 and store the value of the SUCI sent in the REGISTRATION REQUEST message. The UE shall include the stored SUCI in the REGISTRATION REQUEST message while timer T3519 is running / No: continue.
    - The UE is operating in the dual-registration mode and it is in EMM state EMM-REGISTERED? → Yes: include the UE status IE with the EMM registration status set to "UE is in EMM-REGISTERED state" / No: continue.
    - UE supports NSAG? -> Yes: Set the NSAG bit to "NSAG supported" in the 5GMM capability IE. / No: continue
    - UE supports sending of REGISTRATION COMPLETE message for acknowledging the reception of NSAG information IE in the REGISTRATION ACCEPT message? -> Yes: Set the RCMAN bit to "Sending of REGISTRATION COMPLETE message for NSAG information supported" in the 5GMM capability IE. / No: continue.
    - The 5GS registration type IE in the REGISTRATION REQUEST message is not set to "disaster roaming initial registration" and the UE supports S1 mode and the UE has not disabled its E-UTRA capability? -> Yes: set the S1 mode bit to "S1 mode supported" in the 5GMM capability IE, include the S1 UE network capability IE, if the UE supports EPS-UPIP, set the EPS-UPIP bit to "EPS-UPIP supported" in the S1 UE network capability IE. If the UE supports sending an ATTACH REQUEST message containing a PDN CONNECTIVITY REQUEST message with request type set to "handover" to transfer a PDU session from N1 mode to S1 mode, set the HO attach bit to "attach request message containing PDN connectivity request with request type set to handover to transfer PDU session from N1 mode to S1 mode supported" in the 5GMM capability IE / No: continue.

- **State Transitions:**
    - N/A (This section only describes the initial steps of the procedure).
- **Important Information Elements:**
    - 5GS registration type IE: Indicates the type of registration (initial, emergency, SNPN onboarding, disaster roaming).
    - 5GS mobile identity IE: Contains the UE's identity (5G-GUTI, SUCI, or PEI).
    - Requested NSSAI IE: Contains the S-NSSAI(s) corresponding to the slice(s) to which the UE intends to register with.
    - 5GMM capability IE: Indicates the UE's supported features and capabilities.
    - UE status IE: Indicates the EMM registration status when the UE is in dual-registration mode.
    - Last visited registered TAI:  Indicates the last tracking area the UE was registered in.
    - 5GS update type IE:  Indicates whether the UE requests SMS over NAS.
    - MICO indication IE:  Indicates whether the UE supports MICO mode and whether it requests the use of MICO mode.
    - T3324 IE: Indicates the active time value requested by the UE.
    - Requested DRX parameters IE: Indicates the UE specific DRX parameters.
    - Requested extended DRX parameters IE: Indicates the eDRX parameters that the UE requests to use.
    - LADN indication IE: Indicates whether the UE needs to request LADN information for specific LADN DNN(s) or indicates a request for LADN information
    - S1 UE network capability IE: indicates the UE's E-UTRA network capabilities
    - UE radio capability ID IE: contains the network-assigned or manufacturer-assigned UE radio capability ID.
    - Payload container IE: contains the UE STATE INDICATION message carrying the UE policy container.
    - NAS message container IE: Contains the REGISTRATION REQUEST message for security purposes.
    - Additional information requested IE: Indicates whether the UE needs to obtain new ciphering keys for ciphered broadcast assistance data.
    - Requested WUS assistance information IE:  Contains the UE paging probability information for WUS
    - Requested PEIPS assistance information IE:  Contains the UE paging probability information for PEIPS.
    - N5GC indication IE: Indicates whether the W-AGF acting on behalf of an N5GC device initiates an initial registration.
    - AUN3 indication IE: Indicates whether the 5G-RG acting on behalf of an AUN3 device initiates an initial registration.
    - Service-level-AA container IE: Contains service-level-AA container information.
    - UE determined PLMN with disaster condition IE:  Indicates the UE determined PLMN with disaster condition
