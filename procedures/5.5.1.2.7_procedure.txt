Okay, let's break down the key procedural steps outlined in section 5.5.1.2.7 ("Abnormal cases in the UE") within the context of the initial registration procedure. This section dictates how the UE behaves when encountering various error scenarios during the initial registration process.

Here's a summary of the key procedural steps for each abnormal case, focusing on the *UE's actions*:

**a) Timer T3346 is running:**

*   **UE Action:** The UE *shall not* start the initial registration procedure *unless* one of the listed exceptions applies (high priority access, emergency services, re-registration required indication, exception data reporting for NB-N1, emergency PDU session). The UE remains in the current cell and performs normal cell reselection.

**b) Lower layers indicate access is barred:**

*   **UE Action:** The UE *shall not* start the initial registration procedure. The UE stays in the current serving cell and applies normal cell reselection.  The UE waits for the barring to be lifted.

**ba) Lower layers indicate access barring for specific categories:**

*   **UE Action:**
    *   **If REGISTRATION REQUEST not sent:** Proceed as in case b (do not start the registration).
    *   **If REGISTRATION REQUEST has been sent:** Proceed as in case e (abort the procedure). Additionally, after barring alleviation the registration procedure is restarted, if still needed.

**c) T3510 timeout:**

*   **UE Action:** Abort the initial registration procedure and release the NAS signalling connection (if any), *unless* it's for emergency services or initiating an emergency PDU session with an existing emergency PDU session.  Then, proceed to the common actions defined after case 'n'.

**d) REGISTRATION REJECT message (or specific 5GMM cause values):**

*   **UE Action:** If the registration is not for emergency services or establishing an emergency PDU session, and upon reception of the 5GMM causes #95, #96, #97, #99 and #111 the UE should set the registration attempt counter to 5.
*   Then, proceed to the common actions defined after case 'n'.

**e) Lower layer failure/release of NAS signalling connection:**

*   **UE Action:** Abort the initial registration procedure and proceed to the common actions defined after case 'n'.

**f) UE-initiated de-registration required:**

*   **UE Action:** Abort the initial registration procedure and perform the UE-initiated de-registration procedure. Populate the `5GS mobile identity` IE in the `DEREGISTRATION REQUEST` message with the same UE identity used in the aborted `REGISTRATION REQUEST`. If de-registration is due to USIM removal and T3519 is not running, the UE *may* perform a local de-registration.

**g) De-registration procedure collision:**

*   **UE Action:** If a `DEREGISTRATION REQUEST` is received in `5GMM-REGISTERED-INITIATED` state, abort the de-registration procedure and continue the initial registration procedure (if the DEREGISTRATION REQUEST message indicates the access type over which the initial registration procedure is attempted).

**h) Change in current TAI:**

*   **UE Action:** Abort the initial registration procedure and *immediately* re-initiate it.  If a TAI border is crossed *after* receiving `REGISTRATION ACCEPT` but *before* sending `REGISTRATION COMPLETE`:
    *   If the new TAI is in the TAI list, send the `REGISTRATION COMPLETE` message.
    *   Otherwise, abort the initial registration procedure and start the mobility registration update procedure.
    *   If a 5G-GUTI was allocated, use it in the registration procedure.

**i) Transmission failure of REGISTRATION COMPLETE with TAI change:**

*   **UE Action:**
    *   If the current TAI is still in the TAI list, resend the `REGISTRATION COMPLETE` message.
    *   Otherwise, abort the initial registration procedure and start the mobility registration update procedure.

**j) Transmission failure of REGISTRATION COMPLETE without TAI change:**

*   **UE Action:** Implementation-specific on how to re-run the ongoing procedure.

**k) Transmission failure of REGISTRATION REQUEST:**

*   **UE Action:** Abort the initial registration procedure and *immediately* re-initiate it.

**l) Timer T3447 is running:**

*   **UE Action:** The UE *shall not* start the registration procedure for initial registration with Follow-on request indicator set to "Follow-on request pending" unless one of the listed exceptions applies (high priority access, emergency services). The UE remains in the current cell and performs normal cell reselection. The registration procedure for initial registration is started, if still necessary, when timer T3447 expires or timer T3447 is stopped.

**m) UE is not registered to the access other than the access the REGISTRATION ACCEPT message is received and the 5GS registration result value in the 5GS registration result IE value in the REGISTRATION ACCEPT message is set to "3GPP access and non-3GPP access":**

*   **UE Action:** The UE shall consider itself as being registered to only the access where the REGISTRATION ACCEPT message is received.

**n) Access for localized services in current SNPN is no longer allowed:**

*   **UE Action:** If the initial registration request is neither for emergency services nor for initiating a PDU session for emergency services with request type set to "existing emergency PDU session", the selected SNPN is an SNPN selected for localized services in SNPN and:
    *   access for localized services in SNPN is disabled; or
    *   the validity information for the selected SNPN is no longer met;
    *   the UE shall reset the registration attempt counter, stop T3510, abort the registration procedure for initial registration, locally release the NAS signalling connection, if any, and enter state 5GMM-DEREGISTERED.LIMITED-SERVICE or 5GMM-DEREGISTERED.PLMN-SEARCH in order to perform SNPN selection according to 3GPP TS 23.122 [5].

**Common actions (after cases c, d and e):**

*   Stop timer T3510 (if running).
*   Increment the registration attempt counter (unless it's already at 5).
*   **If registration attempt counter < 5:**
    *   Start T3511.
    *   Change state to `5GMM-DEREGISTERED.ATTEMPTING-REGISTRATION`.
    *   Restart the initial registration procedure when T3511 expires (if still required).
*   **If registration attempt counter = 5:**
    *   Delete TAI list and last visited registered TAI.
    *   Start T3502 (if the network-provided value is not zero).
    *   Set 5GS update status to `5U2 NOT UPDATED`.
    *   If not registered to the same PLMN over both accesses, delete 5G-GUTI, ngKSI, and list of equivalent PLMNs/SNPNs (if any).
    *   Change state to `5GMM-DEREGISTERED.ATTEMPTING-REGISTRATION` or optionally to `5GMM-DEREGISTERED.PLMN-SEARCH`.
    *   If T3502 value is zero, perform actions for T3502 expiry.
    *   If the procedure is via 3GPP access and the UE is operating in single-registration mode:
        *   Handle EMM parameters as specified in 3GPP TS 24.301 for EPS attach failures when the attach attempt counter is equal to 5.
        *   Attempt to select E-UTRAN and proceed with EMM procedures.
        *   The UE *may* disable the N1 mode capability.

This detailed breakdown should provide a clear understanding of the UE's procedural steps for handling abnormal cases during initial registration. Remember that some actions are conditional, based on specific circumstances within each case.
