- **Procedure Name:** Initial Registration Initiation
- **Triggering Conditions:**
    - UE is in 5GMM-DEREGISTERED state and needs to perform initial registration for 5GS services.
    - UE is in 5GMM-DEREGISTERED state and needs to perform initial registration for emergency services.
    - UE is in 5GMM-DEREGISTERED state and needs to perform initial registration for SMS over NAS.
    - UE moves from GERAN/UTRAN to NG-RAN coverage and a GPRS attach/routing area updating procedure was initiated in A/Gb or Iu mode, OR the UE performed 5G-SRVCC from NG-RAN to UTRAN, and since then the UE did not perform a successful EPS attach or tracking area updating procedure in S1 mode or registration procedure in N1 mode.
    - UE is in 5GMM-DEREGISTERED state and needs to perform initial registration for onboarding services in SNPN.
    - UE is in 5GMM-DEREGISTERED state and needs to perform initial registration for disaster roaming services.
    - UE is in 5GMM-DEREGISTERED state and needs to perform initial registration to come out of unavailability period and resume normal services.

- **Steps:**
    1. The UE sends a REGISTRATION REQUEST message to the AMF.
    2. The UE starts timer T3510.
    3. If timer T3502 is currently running, the UE stops timer T3502.
    4. If timer T3511 is currently running, the UE stops timer T3511.
    5. If a SUCI is included in the 5GS mobile identity IE and the timer T3519 is not running, the UE starts timer T3519 and stores the value of the SUCI sent in the REGISTRATION REQUEST message. The UE shall include the stored SUCI in the REGISTRATION REQUEST message while timer T3519 is running.

- **Decision Points:**
    - Emergency Registration over Current Access: Already registered for emergency services over the non-current access? → Yes: Do not initiate registration unless for handover of existing emergency PDU session. / No: Proceed with registration.
    - Emergency Registration over non-3GPP Access: Can register for emergency services over 3GPP access? → Yes: Do not initiate registration over non-3GPP. / No: Proceed with registration over non-3GPP.
    - Valid 4G-GUTI Available after Interworking without N26 and "interworking without N26 interface not supported" indication received: Yes -> Create a 5G-GUTI mapped from the valid native 4G-GUTI and indicate the mapped 5G-GUTI in the 5GS mobile identity IE, include the UE status IE with the EMM registration status set to "UE is not in EMM-REGISTERED state" and include an ATTACH REQUEST message in the EPS NAS message container IE./ No -> Continue.
    - Valid 5G-GUTI available: Yes -> include the 5G-GUTI in the Additional GUTI IE in the REGISTRATION REQUEST message in the following order: 1) a valid 5G-GUTI that was previously assigned by the same PLMN with which the UE is performing the registration, if available; 2) a valid 5G-GUTI that was previously assigned by an equivalent PLMN, if available; and 3) a valid 5G-GUTI that was previously assigned by any other PLMN, if available; / No -> Continue.
    - Valid 5G NAS security context: Yes -> send a REGISTRATION REQUEST message including the NAS message container IE if the UE needs to send non-cleartext IEs.  If the UE does not need to send non-cleartext IEs, the UE shall send a REGISTRATION REQUEST message without including the NAS message container IE / No -> send the REGISTRATION REQUEST message without including the NAS message container IE.
    - UE is operating in the dual-registration mode and it is in EMM state EMM-REGISTERED: Yes -> include the UE status IE with the EMM registration status set to "UE is in EMM-REGISTERED state"./ No -> Continue.
    - Ciphered broadcast assistance data is supported and new ciphering keys are requested: Yes -> include the Additional information requested IE with the CipherKey bit set to "ciphering keys for ciphered broadcast assistance data requested"./ No -> Continue.
    - Disaster roaming services and the UE determined PLMN with disaster condition is the HPLMN and:  1) the Additional GUTI IE is included in the REGISTRATION REQUEST message and does not contain a valid 5G-GUTI that was previously assigned by the HPLMN; or 2) the Additional GUTI IE is not included in the REGISTRATION REQUEST message and the 5GS mobile identity IE contains neither the SUCI nor a valid 5G-GUTI that was previously assigned by the HPLMN: Yes -> include in the REGISTRATION REQUEST message the UE determined PLMN with disaster condition IE indicating the UE determined PLMN with disaster condition./ No -> Continue.
    - Disaster roaming services and the UE determined PLMN with disaster condition is not the HPLMN and:  1) the Additional GUTI IE is included in the REGISTRATION REQUEST message and does not contain a valid 5G-GUTI that was previously assigned by the UE determined PLMN with disaster condition; or 2) the Additional GUTI IE is not included in the REGISTRATION REQUEST message and the 5GS mobile identity IE does not contain a valid 5G-GUTI that was previously assigned by the UE determined PLMN with disaster condition: Yes -> include in the REGISTRATION REQUEST message the UE determined PLMN with disaster condition IE indicating the UE determined PLMN with disaster condition./ No -> Continue.

- **State Transitions:**
    - N/A (This excerpt only describes the initial action to *start* the registration procedure).

- **Important Information Elements:**
    - REGISTRATION REQUEST message: The message initiating the registration procedure. Contains various IEs.
    - 5GS mobile identity: Contains either 5G-GUTI, SUCI or PEI depending on the scenario.
    - 5G-GUTI: 5G Globally Unique Temporary Identity.
    - SUCI: Subscription Concealed Identifier.
    - PEI: Permanent Equipment Identifier.
    - Additional GUTI: An additional 5G-GUTI.
    - UE status: Indicates EMM registration status.
    - ATTACH REQUEST message: An EPS ATTACH REQUEST message, encapsulated in the EPS NAS message container IE.
    - EPS NAS message container: Container for EPS NAS messages.
    - Last visited registered TAI: The last Tracking Area Identity where the UE was registered.
    - 5GS update type: Indicates if SMS over NAS is requested.
    - MICO indication: Indicates support and request for MICO mode.
    - T3324: Active time value.
    - Requested T3512: Requested value for the T3512 timer.
    - Requested DRX parameters: UE specific DRX parameters.
    - Requested NB-N1 mode DRX parameters: UE specific DRX parameters for NB-N1 mode.
    - Requested extended DRX parameters: Indicates eDRX parameters requested by the UE.
    - LADN indication: Indicates request for LADN information.
    - Requested NSSAI: List of S-NSSAIs corresponding to slices the UE intends to register to.
    - Network slicing indication: Indicates that the requested NSSAI was created from the default configured NSSAI.
    - 5GMM capability: Contains bits indicating supported features (e.g., NSAG, S1 mode, LPP, etc.).
    - S1 UE network capability: Indicates UE's S1 mode capabilities.
    - Mobile station classmark 2: IE for 5G-SRVCC support.
    - Supported codecs: IE for 5G-SRVCC support.
    - Follow-on request indicator: Indicates that the UE needs to prolong the NAS signalling connection.
    - UE radio capability ID: Identifies the UE radio capability.
    - Payload container type: Indicates the type of payload in the Payload container IE.
    - Payload container: Contains the UE policy container.
    - Additional information requested: Indicates request for ciphering keys.
    - Requested WUS assistance information: Contains UE paging probability information.
    - Requested PEIPS assistance information: Contains UE paging probability information for PEIPS.
    - N5GC indication: Indicates that an N5GC device is requesting registration.
    - AUN3 indication: Indicates that an AUN3 device is requesting registration.
    - Service-level-AA container: Contains service-level-AA information for UAS services.
    - UE determined PLMN with disaster condition: Indicates the UE determined PLMN with disaster condition.
